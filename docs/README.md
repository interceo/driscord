## Что необходимо для работы

Для входа, списка серверов и каналов нужны REST API и PostgreSQL. Для входа в
голосовой канал нужен signaling-сервер — он же переносит медиа: аудио и видео
идут по схеме клиент → сервер → клиенты (SFU), а не напрямую между клиентами.

В текущей конфигурации отдельный STUN/TURN не используется. Клиент
устанавливает WebRTC-соединение только с публичным сервером и получает его
host-кандидаты; для этого нужно открыть указанный ниже UDP-диапазон. Такая
схема не покрывает сети, полностью блокирующие UDP: для них потребуется
TURN/TCP/TLS или другой relay fallback.

Минимальная схема портов:

| Компонент | Порт | Протокол | Назначение |
|---|---:|---|---|
| API | 9002 | TCP/HTTP | Авторизация, серверы, каналы, файлы |
| Signaling | 9001 | TCP/WebSocket | Комната, SDP/ICE |
| Signaling media (SFU) | 49160–49200 | UDP | RTP/RTCP поверх ICE/DTLS/SRTP |

UDP-диапазон задаётся переменными `DRISCORD_ICE_PORT_MIN` и
`DRISCORD_ICE_PORT_MAX`; значения выше — по умолчанию.

`9002` выбран здесь намеренно: его ожидает клиент по умолчанию. Сам API без
конфигурации слушает `8000`, поэтому при развёртывании следует явно задать
`API_PORT=9002` либо изменить клиентский `config.json`.
