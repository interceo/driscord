## Что необходимо для работы

Для входа, списка серверов и каналов нужны REST API и PostgreSQL. Для входа в
голосовой канал нужен signaling-сервер. Само аудио и видео передаются напрямую
между клиентами по WebRTC DataChannel; signaling их не проксирует.

STUN помогает клиенту узнать свой публичный адрес, а TURN ретранслирует медиа,
когда прямое P2P-соединение невозможно. В коде уже задан публичный Google STUN,
но production-инсталляции нужен свой TURN. Это может быть один `coturn`, который
одновременно обслуживает STUN и TURN.

Минимальная схема портов:

| Компонент | Порт | Протокол | Назначение |
|---|---:|---|---|
| API | 9002 | TCP/HTTP | Авторизация, серверы, каналы, файлы |
| Signaling | 9001 | TCP/WebSocket | SDP/ICE и события комнаты |
| coturn | 3478 | UDP и TCP | STUN/TURN |
| coturn relay | 49160–49200 | UDP | Ретрансляция WebRTC-трафика |

`9002` выбран здесь намеренно: его ожидает клиент по умолчанию. Сам API без
конфигурации слушает `8000`, поэтому при развёртывании следует явно задать
`API_PORT=9002` либо изменить клиентский `config.json`.
